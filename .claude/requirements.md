# Whale 프로젝트 요구사항 명세서

> 본 문서는 `/whale-app/`에 구현된 Whale 이미지 튜닝 스튜디오의 기능 요구사항(FR)과 비기능 요구사항(NFR)을 정리한 문서입니다.

## 표기 규약

### 우선순위 (MoSCoW)
- **MUST** — 필수. 미구현 시 제품 가치 상실
- **SHOULD** — 강력 권장. 1차 릴리즈 포함 권장
- **COULD** — 있으면 좋음. 후순위
- **WON'T** — 현재 범위 밖 (의도적 제외)

### 상태
- ✅ 구현됨
- 🟡 부분 구현 (UI만, 동작 mock)
- ⛔ 미구현
- 📌 기획만

### 기술 표기 원칙
- **행위**는 사용자 UX 관점에서 조건 → 액션 → 결과로 기술
- **측정 기준**: 객관적으로 평가 가능한 항목 체크리스트
- **알려진 제약**: 의도적 비지원 또는 현재 한계
- **평가 기준 없음**: 디자인 의도가 모호하거나 객관적 기준 정의 불가
- **구현 위치**: 프로젝트 루트(`/`) 기준 경로

## 1. 기능 요구사항 (FR)

### 1.1 Home 페이지

> **개요**: 사용자가 앱에 진입했을 때 가장 먼저 보는 대시보드. 인사 메시지, 진행 중인 작업 요약, 빠른 액션, 주간 통계, 최근 세션, 활동 로그를 한눈에 보여준다.
>
> **구현 위치**: `/whale-app/src/components/Home.tsx`

---

#### FR-HOME-01 — 인사 메시지 및 진행 요약 표시

| 속성 | 값 |
|------|-----|
| **우선순위** | SHOULD |
| **상태** | 🟡 부분 구현 (정적 텍스트, 데이터 연동 없음) |
| **구현 위치** | `/whale-app/src/components/Home.tsx` |

##### 행위

**조건**: 사용자가 Home 페이지에 진입한다.

**액션**: 페이지가 로드된다.

**결과**:
1. 페이지 상단에 큰 글씨로 인사 메시지가 표시된다: `Good afternoon, Jiwon`
2. 인사 바로 아래 한 줄로 진행 상황 요약이 표시된다: `3 sessions in progress · 48 images tuned this week · 2 reviews awaiting`
3. 인사 메시지는 일반 본문 색, 진행 요약은 muted 색으로 차별 표시된다.

##### 측정 기준

- [ ] 페이지 진입 후 1초 이내에 인사 메시지와 요약이 모두 표시된다.
- [ ] 인사 메시지의 글자 크기가 28px 이상으로 시각적 위계가 가장 높다.

##### 알려진 제약

- ❌ 시간대(아침/점심/저녁)에 따라 인사말이 변하지 않음 — `Good afternoon` 고정.
- ❌ 사용자 이름(`Jiwon`)이 하드코딩되어 있음 — 인증/사용자 컨텍스트 미연동.
- ❌ 진행 요약 수치(3 / 48 / 2)가 정적 텍스트로 하드코딩되어 있음 — 실시간 데이터 연동 없음.

##### 평가 기준 없음

- 인사 메시지에 사용자 직군(엔지니어 등)을 반영해야 하는지에 대한 기준 없음.

#### FR-HOME-02 — 빠른 액션 카드

| 속성 | 값 |
|------|-----|
| **우선순위** | MUST |
| **상태** | 🟡 부분 구현 (E2E/Library 카드만 동작, Upload는 UI만) |
| **구현 위치** | `/whale-app/src/components/Home.tsx` |

##### 행위

**조건**: 사용자가 Home 페이지에서 빠른 액션 영역을 본다.

**액션 1 — Open E2E Pipeline 카드 클릭**:
1. 화면이 즉시 E2E 페이지로 전환된다.
2. 상단 nav의 활성 탭이 [E2E]로 변경된다.

**액션 2 — Browse Library 카드 클릭**:
1. 화면이 즉시 Library 페이지로 전환된다.
2. 상단 nav의 활성 탭이 [Library]로 변경된다.

**액션 3 — Upload Reference 카드 클릭**:
- 시각적 피드백(hover, 클릭 누름)은 발생하지만, 페이지 전환이나 파일 업로드 다이얼로그가 나타나지 않는다.

**공통 시각 표현**:
- 각 카드에는 좌상단에 액센트 색상의 둥근 아이콘 박스가 표시된다 (E2E: pipeline, Library: folder, Upload: upload).
- 카드 제목, 설명 문구, 우하단에 키보드 단축키 칩(`⌘E` / `⌘L` / `⌘U`)이 표시된다.
- 카드에 마우스를 올리면 보더가 액센트 색으로 변하고, 카드 전체가 1px 위로 살짝 떠오른다.
- 3개 카드는 동일한 너비로 가로 정렬된다 (3-column grid).

##### 측정 기준

- [ ] E2E / Library 카드 클릭 시 1초 이내에 페이지가 전환된다.
- [ ] 카드 hover 시 보더 색 변경과 떠오름 효과가 즉시 적용된다 (지연 100ms 이내).
- [ ] 3개 카드의 폭이 정확히 동일하다 (반응형 그리드 깨짐 없음).

##### 알려진 제약

- ❌ 키보드 단축키 칩(`⌘E` / `⌘L` / `⌘U`)은 시각적 표시일 뿐 실제 키 입력으로 동작하지 않음.
- ❌ Upload Reference 카드는 클릭해도 동작 없음 — 파일 다이얼로그 또는 업로드 흐름 미구현.

##### 평가 기준 없음

- 카드 떠오름 애니메이션의 지속 시간 및 easing 곡선에 대한 명시 기준 없음.

#### FR-HOME-03 — 주간 통계 (Overview · this week)

| 속성 | 값 |
|------|-----|
| **우선순위** | SHOULD |
| **상태** | 🟡 부분 구현 (정적 데이터) |
| **구현 위치** | `/whale-app/src/components/Home.tsx` |

##### 행위

**조건**: 사용자가 Home 페이지를 스크롤하거나 진입한다.

**액션**: 빠른 액션 카드 아래의 Overview 섹션이 표시된다.

**결과**:
1. 섹션 헤더에 `Overview · this week` 라벨과 우측에 모노스페이스로 `week 16 · Apr 13 – Apr 19` 기간 표시가 함께 나타난다.
2. 그 아래 가로 4-column 그리드로 통계 카드 4개가 표시된다:

   | 라벨 | 값 | 보조 정보 |
   |------|-----|----------|
   | Images tuned | `48` | `↑ 12 vs last week` (녹색) |
   | Active sessions | `3` | `night · auto · hdr-a` |
   | ΔE avg (target) | `2.14` | `target ≤ 3.0` |
   | Library | `1,284` | `420 ref · 864 sim` |

3. 통계 값은 큰 글씨(22px) 모노스페이스로, 라벨은 작은 대문자로 표시된다.
4. Images tuned 카드의 `↑ 12 vs last week`는 녹색(ok) 텍스트로 양적 증가를 시각적으로 강조한다.

##### 측정 기준

- [ ] 4개 카드의 폭이 정확히 동일하다.
- [ ] 통계 값은 모노스페이스 + 자릿수 정렬(tabular-nums)로 시각적으로 정렬된다.
- [ ] 카드 내부 패딩이 일관되어 텍스트가 카드 경계와 겹치지 않는다.

##### 알려진 제약

- ❌ 주간 통계 4개 모두 하드코딩 — 백엔드/계산 로직 미연동.
- ❌ 표시 기간(`week 16 · Apr 13 – Apr 19`)이 고정 텍스트 — 실제 현재 주차로 갱신되지 않음.
- ❌ 카드 클릭 시 상세로 이동하는 인터랙션 없음.
- ❌ ΔE avg가 target을 초과할 경우 경고 색으로 강조하는 동작 없음 (현재 항상 같은 색).

##### 평가 기준 없음

- 통계 카드를 4개 이상으로 확장할 때의 레이아웃 규칙 (몇 행으로 줄바꿈할지 등) 명시 기준 없음.

#### FR-HOME-04 — 최근 세션 (Recent sessions)

| 속성 | 값 |
|------|-----|
| **우선순위** | MUST |
| **상태** | 🟡 부분 구현 (정적 카드, 모든 클릭이 동일하게 E2E로 이동) |
| **구현 위치** | `/whale-app/src/components/Home.tsx` |

##### 행위

**조건**: 사용자가 Home 페이지에서 Recent sessions 섹션을 본다.

**액션 1 — 섹션 진입**:
- 섹션 헤더에 `Recent sessions` 제목과 우측에 `View all >` 버튼이 표시된다.
- 그 아래 가로 3-column 그리드로 세션 카드 3개가 표시된다:

  | 카드 | 시간 | ΔE | 태그 |
  |------|------|-----|------|
  | Night scene · sensor-A v3 | 2 min ago | 2.8 | night, low-light, **active** |
  | HDR · outdoor portrait | 1h ago | 1.9 | hdr, skin, **active** |
  | ColorChecker SG · D65 | Yesterday | 1.2 | chart, calibration, **active** |

- 각 카드는 다음 구조로 표시된다:
  - 상단: 두 개의 reference / simulation 썸네일이 좌우로 분할된 미리보기 영역 (높이 150px)
  - 미리보기 하단에 어두운 그라데이션 오버레이
  - 중단: 세션 이름(좌, 잘리면 ellipsis) + ΔE 값(우, 모노스페이스)
  - 하단: 일반 태그들 + 액센트 색의 `active` 배지

**액션 2 — 카드 클릭**:
1. 카드(어느 카드든 동일)를 클릭하면 화면이 즉시 E2E 페이지로 전환된다.
2. 상단 nav가 [E2E]로 변경된다.

**액션 3 — View all 버튼 클릭**:
- 시각적 피드백만 있고 페이지 전환이나 모달 표시 등의 동작이 발생하지 않는다.

**액션 4 — 카드 hover**:
- 카드 보더가 강조 색(`--border-strong`)으로 변경된다.

##### 측정 기준

- [ ] 카드 클릭 시 1초 이내에 E2E 페이지로 전환된다.
- [ ] 세션 이름이 카드 폭을 초과할 경우 말줄임표(`…`)로 잘려 표시되며 줄바꿈되지 않는다.
- [ ] 3개 카드의 미리보기 영역 높이가 정확히 동일하다 (150px).

##### 알려진 제약

- ❌ 모든 세션 카드 클릭이 같은 E2E 페이지로 이동 — 클릭한 세션의 컨텍스트(이름/블록 상태 등)가 E2E 페이지에 반영되지 않음.
- ❌ `View all` 버튼은 동작하지 않음 — 전체 세션 리스트 페이지/모달 미구현.
- ❌ 카드 데이터 3개 모두 하드코딩 — 실제 사용자의 최근 작업 이력 미연동.
- ❌ 썸네일이 placeholder 패턴(스트라이프) — 실제 이미지 표시 안 됨.
- ❌ `active` 배지가 모든 카드에 동일하게 표시 — 실제 활성 여부와 무관.

##### 평가 기준 없음

- 카드 개수가 3개 이상일 경우의 페이징/캐러셀 동작 기준 없음.
- 시간 표시(`2 min ago` / `Yesterday`) 포맷의 자동 갱신 정책 기준 없음.

- [ ] 항목 간 구분선이 마지막 항목 이후에는 표시되지 않는다.

- ❌ 시간 표시(`12:44` / `Yesterday` / `Apr 16`)가 자동 갱신되지 않음.
- ❌ 사용자별/유형별 필터 미구현.

##### 평가 기준 없음

- 항목 개수가 많아질 때의 페이징, 무한 스크롤, "더 보기" 등의 동작 기준 없음.

### 1.2 Library 페이지

> **개요**: 사용자가 그동안 작업한 reference / simulation 이미지를 한곳에서 관리하는 페이지. 좌측 사이드바로 컬렉션 · 세션 · 태그를 필터링하고, 우측 메인 영역에서 Grid 또는 List 뷰로 항목을 보고 다중 선택해 일괄 액션(태그 추가, 즐겨찾기, E2E로 보내기 등)을 수행한다.
>
> **구현 위치**: `/whale-app/src/components/Library.tsx` · `/whale-app/src/data.ts`

#### FR-LIB-01 — 페이지 레이아웃 (사이드바 + 메인 영역)

| 속성 | 값 |
|------|-----|
| **우선순위** | MUST |
| **상태** | ✅ 구현됨 |
| **구현 위치** | `/whale-app/src/components/Library.tsx` |

##### 행위

**조건**: 사용자가 상단바에서 [Library] 탭을 클릭한다.

**액션**: Library 페이지가 로드된다.

**결과**:
1. 화면이 좌측 220px 폭의 **사이드바**와 우측 가변 폭의 **메인 영역**으로 2분할된다.

- [ ] Grid 뷰에서 컨테이너 폭이 변할 때 카드가 잘리거나 가로 스크롤이 생기지 않는다.
- [ ] List 뷰에서 헤더와 모든 행의 컬럼 폭이 정확히 일치한다.
- [ ] 뷰 전환 후 선택된 항목 표시(체크박스 / 액센트 보더)가 그대로 유지된다.
- [ ] 뷰 전환은 1초 이내에 완료된다.

##### 알려진 제약

- ❌ 사용자가 마지막에 선택한 뷰 모드가 페이지 재방문 시 유지되지 않음 (localStorage 등 영구 저장 미구현).
- ❌ List 뷰의 컬럼 폭은 고정 비율이며 사용자가 드래그로 조절할 수 없다.
- ❌ List 뷰에서 컬럼 헤더 클릭으로 정렬 기능이 동작하지 않음.
- ❌ 행/카드의 더보기(`···`) 버튼 클릭 시 컨텍스트 메뉴가 나타나지 않음.
- ❌ List 뷰는 `<table>` 대신 div + grid로 구현되어 있어 스크린리더 호환성이 떨어진다 (시멘틱 손실).

##### 평가 기준 없음

- 카드 최소 폭(현재 190px) 결정의 디자인 기준 명시 없음.
- 서브바에 표시된 `sort: date ↓` / `· group: session` 텍스트가 실제 정렬/그룹 동작을 의미하는지에 대한 기준 없음 (현재는 정적 라벨).

#### FR-LIB-07 — 다중 선택 및 일괄 액션

| 속성 | 값 |
|------|-----|
| **우선순위** | MUST |
| **상태** | 🟡 부분 구현 (선택만 동작, 일괄 액션 4종 모두 mock) |
| **구현 위치** | `/whale-app/src/components/Library.tsx` |

##### 행위

**조건**: 사용자가 Library 페이지 메인 콘텐츠를 본다. 진입 시 ID 1, 2 항목이 기본 선택 상태이다.

**액션 1 — Grid 뷰 카드 클릭 / List 뷰 행 클릭**:
1. 클릭한 항목의 선택 상태가 토글된다 (선택 ↔ 해제).
2. Grid 뷰: 카드 보더가 액센트 색으로 변하고, 외곽에 글로우(`box-shadow`)가 표시되며, 좌상단에 액센트 색 체크박스가 나타난다.
3. List 뷰: 행 배경이 `--accent-soft`로 변하고, 좌측 체크박스가 액센트 색으로 채워진다.
4. 같은 항목을 다시 클릭하면 선택 해제된다.

**액션 2 — Grid 뷰 카드 hover**:
- 비선택 카드는 hover 시 좌상단에 빈 체크박스가 미리 보여진다 (선택 가능함을 시각적으로 시사).

**액션 3 — 선택 개수 표시 (서브바)**:
- 서브바 좌측에 `{filtered.length} of {LIB_ITEMS.length} items · {selected.size} selected` 형식으로 모노스페이스 표기된다.

**액션 4 — 선택된 항목이 1개 이상일 때**:
서브바에 다음 4개 액션 버튼이 동적으로 등장한다:
- `Tag` (태그 아이콘 + 라벨)
- `Add to…` (폴더 아이콘 + 라벨)
- `Favorite` (별 아이콘 + 라벨)
- `Compare in E2E` (split 아이콘 + 라벨, primary 스타일)

선택이 0개로 돌아가면 4개 버튼이 사라진다.

**액션 5 — 액션 버튼 클릭**:
- 시각적 피드백(hover, 클릭 누름)만 있고, 실제 동작이 발생하지 않는다.

##### 측정 기준

- [ ] 항목 클릭 후 즉시(100ms 이내) 선택 표시가 시각적으로 반영된다.
- [ ] 선택 개수가 서브바에 정확하게 표시된다.
- [ ] 일괄 액션 버튼은 선택 0개일 때 사라지고, 1개 이상일 때 등장한다.
- [ ] 뷰 전환(Grid ↔ List) 후에도 선택 상태가 유지된다.

##### 알려진 제약

- ❌ Shift + 클릭으로 범위 선택 미지원.
- ❌ 전체 선택 / 전체 해제 토글 버튼 없음.
- ❌ `Tag`, `Add to…`, `Favorite`, `Compare in E2E` 버튼 4종 모두 동작하지 않음 — 모달/액션 흐름 미구현.
- ❌ 페이지 진입 시 ID 1, 2가 기본 선택된 것은 데모 목적 하드코딩이며, 실제 사용 시나리오에서는 비어있어야 자연스럽다.
- ❌ ESC 키로 선택 해제 미지원.

##### 평가 기준 없음

- 일괄 액션 버튼이 등장/사라질 때의 애니메이션 기준 없음 (현재는 즉시 표시/숨김).

#### FR-LIB-08 — 즐겨찾기 및 메타데이터 표시

| 속성 | 값 |
|------|-----|
| **우선순위** | SHOULD |
| **상태** | 🟡 부분 구현 (즐겨찾기 시각 표시만, 토글 기능 미구현) |
| **구현 위치** | `/whale-app/src/components/Library.tsx` |

##### 행위

**조건**: 사용자가 Library 페이지에서 이미지 항목을 본다.

**액션 1 — 즐겨찾기 시각 표시**:
- Grid 뷰: 카드 우상단에 별 아이콘 버튼이 항상 표시된다.
  - `fav: true` 항목 → 노란색 채워진 별 (`oklch(0.75 0.15 75)`)
  - `fav: false` 항목 → 회색 빈 별 (`--fg-subtle`)
- List 뷰: 파일명 좌측에 `fav: true`인 경우만 작은 노란 별 아이콘이 인라인으로 표시된다.

**액션 2 — Grid 뷰 별 버튼 클릭**:
- 클릭 이벤트가 카드 클릭으로 전파되지 않는다 (`stopPropagation` 적용 → 선택 토글 안 됨).
- 시각적 피드백(hover, 클릭 누름)만 있고, 즐겨찾기 상태 토글이 발생하지 않는다.

**액션 3 — Source 배지 표시**:
- Grid 뷰: 썸네일 좌상단에 `REF` 또는 `SIM` 배지 (소문자 → 대문자 변환).
  - `ref` 항목은 일반 배지 스타일, `sim` 항목은 `sim` 보조 스타일 적용.
- List 뷰: Source 컬럼에 동일한 배지 표시.

**액션 4 — 메타데이터 표시**:
- Grid 뷰 카드 하단:
  - 파일명 (예: `night_0042_ref.dng`) — 모노스페이스, 11px, 한 줄 ellipsis
  - 크기 (예: `6000×4000`) 좌측 + 날짜 (예: `Apr 18`) 우측 — 모노스페이스, 10px
- List 뷰 행:
  - 파일명, 소스 배지, 태그(최대 3개 칩), 세션, 크기, 날짜 — 각 컬럼별 정렬

##### 측정 기준

- [ ] `fav: true` 항목과 `fav: false` 항목의 별 색상이 명확히 구분된다.
- [ ] 별 버튼 클릭 시 카드 선택 상태가 변경되지 않는다 (이벤트 전파 차단 확인).
- [ ] Grid 뷰 파일명이 카드 폭을 초과할 경우 말줄임표(`…`)로 잘려 한 줄로 표시된다.
- [ ] List 뷰 태그 칩이 컬럼 폭을 초과하지 않고 잘려서 표시된다 (overflow hidden).

##### 알려진 제약

- ❌ 별 버튼 클릭 시 `fav` 상태가 토글되지 않음 — 데이터를 state로 끌어올리는 로직 미구현.
- ❌ 즐겨찾기 변경 사항이 영구 저장되지 않음 (페이지 새로고침 시 초기 상태로 복귀).
- ❌ List 뷰에서 태그가 4개 이상인 항목은 처음 3개만 표시되며 "+N more" 같은 인디케이터가 없다.
- ❌ 우측 더보기(`···`) 버튼은 시각적 표시만 있고 동작 없음.
- ❌ List 뷰 썸네일 클릭 시 행 클릭과 동일한 선택 토글이 발생한다 (확대 미리보기 등 별도 동작 없음).

##### 평가 기준 없음

- 즐겨찾기 별 색상(`oklch(0.75 0.15 75)`) 선택의 디자인 기준 명시 없음.
- List 뷰의 인라인 별 아이콘과 Grid 뷰의 별 버튼이 서로 다른 인터랙션을 가져야 하는지에 대한 기준 없음.
